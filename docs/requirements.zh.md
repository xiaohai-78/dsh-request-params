# 需求

请求参数必须做到什么，以及每一部分是怎么验证的。需求只在这里写一份：一个功能在 `.scratch/<功能>/` 下的需求稿，做完后并进这里。用词以 [GLOSSARY.zh.md](../GLOSSARY.zh.md) 为准；设计背后的理由见 [docs/adr/](adr/)。

## 给谁用

让 DSH 的模型请求经过网关的人：OpenRouter、公司的中转，或自建的 vLLM。网关认一些 DSH 不发的字段，比如 OpenRouter 的供应商路由、备用模型、思考预算、为了缓存命中的会话 ID。没有这个插件，要加这些就得改代码。

## 目标

- 在页面上给选定渠道的请求添加、替换或删除请求体字段和请求头。
- 发送之前就能看到请求会带上什么，发送之后能看到网关返回了什么。
- 优先提供渠道协议认的参数种类。

## 不做的事

- 不改请求发往的地址，不转发、不代理请求。

## 约束

- 协议只决定哪些种类排在前面、目录提示有多确定；参数始终按写的原样发出。
- 渠道协议不认的种类折叠在「其他种类」下，从不隐藏。
- OpenRouter 目录的提示标明出处：只对 openrouter.ai 算事实，对其他网关只作参考。
- 认证类请求头（`Authorization`、`x-api-key`、`Cookie` 等）永远不能改；核心字段（`messages`、`model` 等）除非自定义参数明确允许，否则不能改。
- 参数只存在本机；请求记录只放在内存里，从不保存对话。
- 插件只为两件事联网：读 OpenRouter 的公开目录，和检查更新。
- 页面跟随 DSH 的语言，所有文字都有中英文。
- 页面里能检查新版本并升级插件。
- 页面绘制出错时显示错误原文和「重新加载」，不会是一片空白。
- 支持 Windows、macOS、Linux，Node `^22.19.0 || >=24`。
- README 和市场介绍只写验证过的事。

## 功能

### 按渠道加参数

**验收标准**

- 页面列出 DSH 已配置的渠道，以及每个渠道发往的地址。
- 加在某个渠道上的参数作用于这个渠道的请求；发往其他地址的参数放在「其他地址」下，自己写明主机、模型和路径。
- 参数在请求离开 DSH 之前加上，适用于官方 DeepSeek 渠道，以及 `llm-pi-ai` 的 OpenAI 兼容和 Anthropic 兼容渠道（[ADR 0002](adr/0002-parameters-are-applied-by-wrapping-fetch.zh.md)）。

**验证记录**

- 在真实的 dsh 进程里配合本地模拟模型服务，三种渠道都收到了加在各自渠道上的参数，在实际发出的请求里能看到。

### 渠道认哪些字段

**验收标准**

- 每个渠道显示它的协议：认哪种请求格式，以及在格式之外还认哪些字段，根据 DSH 的设置和地址自动识别。
- 协议可以按地址手动设定，也能恢复自动识别（[ADR 0001](adr/0001-protocols-belong-to-addresses.zh.md)）。
- 协议认的种类排在前面，越专门的越靠前；其余放在「其他种类」下，每个都标出它需要什么。

**验证记录**

- 给一个兼容 OpenAI 的中转勾上 OpenRouter 扩展后，这个渠道上可以加供应商路由，中转在收到的请求里拿到了它。

### 参数种类

**验收标准**

- 供应商路由、思考强度、额外采样参数、会话粘滞、应用署名、删除字段，以及自定义字段和请求头，各自加上 README 里列出的字段和请求头。
- 值里可以用 `{{model}}`、`{{session}}` 和 `{{env:NAME}}`；来自环境变量的值从不显示。
- 参数从上到下执行，靠后的能看到前面改过的结果。

**验证记录**

- 按渠道加的参数，在模拟模型服务收到的请求里都能看到。

### 供应商路由

**验收标准**

- 供应商从搜索里挑选，提供预览模型的排在前面，并显示价格和可用率。
- 不提供预览模型的供应商会被标出；在 openrouter.ai 上，会因「No endpoints found」失败的列表在保存前就会提醒。
- 在其他网关上，这些提示标为仅供参考，供应商名可以直接输入。

**验证记录**

- 供应商搜索和「不提供该模型」提示，对照 OpenRouter 公开的目录正常工作，没有向 OpenRouter 发过请求。

### 预览和试运行

**验收标准**

- 「发送时加上」用 JSON 显示一个渠道的参数会给所选模型的请求加上什么，包括还没保存的修改，不发出任何请求。
- 试运行显示加参数前后的完整请求。

**验证记录**

- 预览在真实的 dsh 进程里做过端到端检查。

### 请求记录

**验收标准**

- 每个渠道显示最近的请求：状态、加了什么，网关拒绝时还有它返回内容的开头。
- 请求记录列出 DSH 发出的每个模型请求，最多最近 50 个，只放在内存里。

### 安全

**验收标准**

- 受保护的字段和请求头不能设置或删除；有问题的参数不会生效，页面会指出哪里不对。
- 应用参数出错时，请求原样发出，记录里写明原因。

**验证记录**

- 规则引擎和 `fetch` 包装的测试覆盖了受保护字段、链式安全，以及出错后请求原样发出。

### 日常使用

**验收标准**

- 一个开关能暂停所有参数。
- 没保存的修改在离开页面后仍在，Ctrl/⌘ + S 保存。
- 删除参数可以撤销。
- 规则文件在别处被改时能发现，不会覆盖。
- 参数可以导出和导入 JSON。
- 页面在浅色和深色主题下可用，窄到手机宽度也能用。

**验证记录**

- 保存、暂停、撤销、导入导出、规则文件在别处被改，都做过端到端检查，覆盖浅色、深色、窄屏和手机宽度布局。

### 插件自身的更新

**验收标准**

- 有新版本时页面会提示，用户确认后通过 DSH 的插件管理器安装（[ADR 0003](adr/0003-plugin-updates-itself-through-dsh-plugin-manager.zh.md)）。
- 自动检查可以关掉；本地开发安装从不检查。
- 升级之后，新版本会说明它已经在运行。

**验证记录**

- 在 dsh 0.2.1-rc.2 上对着真实的 npm 源，标成 0.0.9 的副本发现了 0.1.0，「升级…」通过 DSH 的安装器装上了它，配置随后依赖 0.1.0 的压缩包，新版本不用重启就换上了。
- 再装一次同一个版本，会提示已经装好、重启后生效。

### 页面出错时

**验收标准**

- 页面绘制时出错，显示错误原文和「重新加载」按钮，点了重新加载页面。
